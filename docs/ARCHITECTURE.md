# Teo Studio：架构方向

此文件约束高层分工，不固定数据库表或 API 字段。详细开发设计和测试验收计划应由实施者在业务开发前建立，并随实现维护。

## 组件

```text
PWA 界面 ─────┐
              ├─ 共用业务服务层 ─ SQLite（配置、索引、草稿、执行和提醒）
工作台 MCP ───┘          │
                         ├─ 来源适配器 ─ Jira / GitHub / 邮箱 / Markdown
后台调度 ────────────────┤
                         └─ 引擎适配器 ─ Codex / Claude
```

前端建议 React + TypeScript；后端 Python，API 与持久后台执行解耦。SQLite 放运行主机本地，多台电脑通过服务访问，不直接共享打开数据库文件。

正式任务内容属于各来源。SQLite 中的索引缓存可以刷新重建；配置、未提交草稿、审核结果和执行历史需可靠保存与备份。

## 引擎与配置

Codex 接入方向为 App Server；Claude 为 Python Agent SDK + API Key。具体 SDK 版本和接口以实施时官方文档及验证结果为准。默认引擎可被处理方案或单任务覆盖；已有 session 不因全局设置改变而迁移。

三类配置：任务处理方案、任务发现方案、主动关注规则。共用引擎、连接、Skill 和触发机制；10分钟为可修改默认值。

## 可靠性

- 区分任务状态、执行状态、成果审核状态、来源操作状态。
- AI 等待人工时持久化问题和成果，之后续接指定会话；原生权限请求的恢复能力单独验证。
- 读取来源和 AI 分析进度分别保存，避免分析失败后漏掉已读取材料。
- 外部写回使用明确版本、唯一操作记录及结果核验；未知结果不能盲目重试。
- 重复触发、重复发送、过期表单更新及重复通知需要在开发设计中明确处理。
- 前端与 MCP 复用这些规则，不直接绕过服务层操作数据库或源端。

## 交付验证

测试覆盖真实 Markdown 读写、双引擎交互、候选审核、后台检查、人工续接、来源冲突和 MCP 操作。Mock 测试与真实账号联调分开记录；无凭据/缺少运行环境标记待验证，不能算通过。

本期无登录、不自动公网部署。PWA 安装、可信网络访问和源端账户由实际运行环境配置。
