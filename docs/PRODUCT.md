# Teo Studio：产品约定

本文件是产品层级契约；实现细节由开发者设计，细致交互在开发中迭代。

## 核心对象

- Task：目标、来源、关联资料及处理配置。
- Source：正式数据来源。外部任务在原平台；无外部来源的任务在自有 Markdown folder。
- Project：工作台任务分组；无 Project 的任务称为根任务，不表示父子关系。
- Skill：处理方法；Connection：访问资源的账户和工具；Engine：Codex 或 Claude。
- Trigger：手动、时间、周期或事件触发。不建立预设任务类型体系。
- Run：一次 AI 处理，关联原生会话、问题、成果和操作结果。
- View：个人、团队、Project 等筛选范围；Board 和列表是展示方式。

## 创建与编辑

首页快速输入后形成同一份结构化草稿。信息不足立即显示预填表单和缺失必填项；保留对话输入，支持 AI 与手动交替补全，不能静默覆盖用户修改。候选任务经人工审核才创建或关联已有任务。

编辑正式任务必须写回来源后刷新索引。来源失败显示未同步；缓存不成为正式数据。Project 归属、关注和 AI 配置等平台属性独立保存。Markdown 目录可配置，具体文件格式由开发设计确定。

## AI 辅助

任务可选引擎、Skill、Connection、上下文和输出要求。AI 先做明确步骤，需要人工输入或审核时暂停。问题、草稿与对应 session 保存到任务下，用户回答后继续。执行成功不自动等于任务完成。

邮件是一个处理场景：AI 拟稿，人在工作台修改并点击发送回复，结果回到原平台。通用任务也可以生成周报等成果，不建设独立周报模块。

## 主动能力

1. 按配置扫描邮箱、Jira、文档等渠道发现候选任务。
2. 检查已有任务进展，识别停滞或需要关注的变化并汇报。

默认每10分钟检查，可按方案修改。没有新内容时避免重复 AI 分析；到期/跟进时间即使内容不变也需要检查。提醒应去重、允许稍后关注。

## 工作台自身 MCP

平台提供 MCP Server，供 Claude、Codex 等外部 AI 调用。覆盖任务创建、查询、编辑、归档、Project、处理启动/续接、问题回答和成果操作。

MCP 与前端共用服务层。来源权限、版本冲突、候选确认、成果审核与防重复写回规则一致。是否暴露发送等动作以及远程 MCP 的访问边界须在实现中明确；不因拥有 MCP 就绕过人工确认。

## 界面

参考 TickTick 的三栏结构、浅灰侧栏、蓝色强调和紧凑任务列表。首页提供快速输入、需要我处理、值得关注和 AI 进展；侧栏进入个人、团队及 Project 的列表/Board；详情中完成编辑和人工协作。

产品名暂定 Teo Studio，Teo 呼应 Tea；图标为茶杯、茶叶蒸汽与轻量 AI 星芒。

## 边界

- 首期同时支持 Codex 与 Claude，可同时配置，单次执行固定一个。
- Python 后端，SQLite 保存平台相关状态，PWA 提供独立应用窗口。
- 本期不做登录；部署应限定本机或受信网络。
- 真实邮箱、Jira 部署与权限待配置。未验证能力不可显示为接入成功。
